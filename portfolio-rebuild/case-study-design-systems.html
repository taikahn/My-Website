Case Study

Complex Design Systems

Building design systems that serve both product design and engineering requires more than a UI library. It requires structure, naming discipline, states, theming logic, and practical documentation.

Reduce design inconsistency and make implementation more understandable and efficient

Overview

Creating systems that reduce friction

At Strata Identity I created multiple Figma-based design systems that helped organize the product UI into reusable, predictable, and scalable patterns. A major part of the work involved variables and token-like structures that made dark and light mode management far more efficient.

Beyond the design library, I also built a React-oriented system view focused on what was actually live. That meant engineering could reference the most relevant elements in their current states rather than sorting through an overly abstract system disconnected from production reality.

“

A useful design system is not just organized. It is interpretable, maintainable, and close enough to production that teams can actually trust it.

Problem

Bridging the gap between design libraries and shipped UI

Many systems fail because they become either too abstract for developers or too incomplete for designers. The challenge here was to create a system that felt flexible enough for exploration while still being concrete enough to support implementation, theming, and daily product decisions.

System principles

Useful, documented, and close to implementation

Theme flexibility

Variables allowed visual updates to cascade cleanly across components, improving consistency and making multi-mode design much easier to manage.

State coverage

Components were organized with attention to hover, selected, disabled, empty, and other real product states that often get overlooked in superficial systems.

Developer clarity

A more practical, commented React version made it easier for engineering to understand intent, locate live UI pieces, and align implementation with design decisions.

What the system included

Structures that made the work reusable

Variables and modes

Theme-aware foundations that supported fast transitions between dark and light interfaces.

Component states

Coverage for real-world interaction scenarios instead of idealized UI only.

Live references

A React-oriented version that reflected current implementation reality.

Documentation value

Clearer system communication for designers and engineers working together.

Screens

Selected visuals

Outcome

A design system that worked for both design and code

The most valuable systems are the ones people actually use. This work aimed to make the system practical, navigable, and directly useful to multiple audiences: designers shaping new work and developers building and maintaining the shipped interface.

The result was better consistency, more understandable component logic, and a stronger shared foundation for collaboration between design and engineering.

By pairing visual consistency with implementation awareness, the system became more than a style guide. It became a shared product language.
